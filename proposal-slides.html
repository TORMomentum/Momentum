Our solution · architecture & trust5 / 9

A boring, provable stack — built to be defensible

Ingestupload · URL · API
→
MinIOimmutable raw docs
→
Vertex AIThai OCR + extraction
→
MongoDB Atlasstructured metadata
→
Express APImatch · notify · serve
→
Next.jsdashboard · Thai UI
  • Raw documents never enter the database — object storage only.
  • Docker Compose everywhere: identical dev, CI, pilot; tests on every PR.
  • Security baseline: hashed credentials, HTTPS, RBAC, rate-limited API.
  • Flags say "statistical anomaly" — never "suspicious." Unverified fields never feed anomaly stats or match emails.
  • Every record links to its source + shows extraction provenance; dashboard shows "data last updated" + coverage note.
  • PDPA-aligned: consent, PII minimization, export/delete, takedown workflow — no legal certification claimed.

S1 · Validatewk 1–3 · Inception → ElaborationInterviews → revised backlog · TOR corpus · accuracy benchmark · CI/Docker
S2 · Ingestwk 4–6 · Elaboration → ConstructionUpload/URL/API → extraction → review queue → detail page
S3 · Showwk 7–9 · ConstructionPublic dashboard · pricing plots · anomaly rule · search
S4 · Matchwk 10–12 · ConstructionProfiles · matching engine · email notifications

Cost control by phase gate: the effort budget is partitioned per phase; Jira actuals are compared at every gate, so overrun is visible weeks early — and the fix is cutting Sprint-5 scope, never squeezing test at the end. If S1 extraction accuracy is insufficient, the plan changes before further build.

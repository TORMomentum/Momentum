The system · functional features2 / 15

Procurement documents in, public and vendor data out.

Problem

Agencies publish TORs on dozens of sites as PDFs and scans. A small vendor cannot watch them all and a citizen cannot compare them.

What it does

  • Collects TORs; stores each original immutably
  • AI extraction (Document AI + Gemini) with confidence tiers
  • Search, TOR detail, public dashboard, anomaly rule
  • Vendor accounts, profiles, matching, private document vault
  • Admin review queue, takedown with audit trail

Why security matters here

  • Accounts and vendor-private files (PDPA-aligned)
  • Admin power over what the public sees
  • Untrusted uploads and URLs; AI processes them
  • Paid cloud calls an attacker could run up

Design principles · Lecture 711 / 15

Fourteen of fifteen followed. One is still planned.

  • Least privilege: separate keys, vendor scope
  • Defense in depth: five layers on every upload
  • Fail securely: errors deny; config fails fast
  • Secure defaults: risky features ship off
  • Separation of privilege: staff pass + role
  • Complete mediation: no signed URLs
  • Open design: public anomaly method
  • Zero trust: files, URLs, AI output verified
  • Privacy by design: one redaction point
  • Never assume secrets are safe: hashed, gitignored
Partly / planned: separation of duties (admins still share one key) and securing the weakest link (that shared key is the top-risk threat, T02).
